# Fault and alarm codes

The platform's codes, the same in every product of the family (Common Instrument Platform
Specification CIP-11.3). Platform alarms are 1-99; each product lists its own from 100 in
its own `FAULT_CODES.md`. **Generated by `make fault-codes` from the firmware's tables (`tools/fault_codes.c`); do not edit by hand.** `make test` fails if it is out of date.

## Alarms

Severity: status < warning < alarm < fault. The behaviour column is the default; the user
can change each alarm's actions (email, Modbus common bit, relays) with parameter 46.
Active alarms are in the Modbus registers 10-25 (one bit per ID) and on `/api/alarms`.

| ID | Name | Severity | Behaviour (default) | Text | What to check |
|---|---|---|---|---|---|
| 1 | `CAL_INVALID` | fault | email, Modbus | No valid calibration data: measurement blocked | Neither copy of the factory data in the settings memory is valid (new unit, or memory fault). Calibrate at factory login, or restore a backup taken from this unit. |
| 2 | `PARAM_WRITE_FAIL` | fault | on after 2.0 s, email, Modbus | Settings memory fault: changes may not be kept | The settings memory (FRAM) did not verify a write, or is not fitted (RAM fallback). Check the FRAM; changes made now may be lost at power-off. |
| 3 | `LOG_STORAGE_FAULT` | fault | email, Modbus | Log memory fault: records are not being kept | The log flash failed an erase, write or read-back. Records are not being kept. Replace the core board if it persists. |
| 4 | `IP_CONFLICT` | alarm | email, Modbus | IP address in use by another device: network off | Another device answers at this unit's static IP address; the plant port is off until it is free. Change one of the addresses. |
| 5 | `REMOTE_LINK_LOST` | alarm | email, Modbus | Remote control: no messages from the control system | In REMOTE mode and no Modbus or web traffic from the control system for the timeout (parameter). Check the network and the PLC. |
| 6 | `UNEXPECTED_RESET` | warning | latching, Modbus | The unit restarted itself (watchdog or supply dip) | The watchdog or a supply dip restarted the unit. The last fault on the System screen says which task or check stopped. Acknowledge to clear. |
| 7 | `FW_ROLLED_BACK` | warning | latching, Modbus | Firmware update failed its trial and was undone | A new firmware image restarted during its trial, so the previous image was put back. Acknowledge; report the version to the manufacturer. |
| 8 | `DISPLAY_FAULT` | warning | on after 5.0 s, Modbus | Touchscreen not responding | The touchscreen stopped answering. Check its ribbon cable; the unit keeps measuring and the web page still works. |
| 10 | `NOTIFY_FAIL` | warning | Modbus | Alarm email could not be sent | An alarm email could not be sent after retries. Check the mail server settings and the network. |
| 11 | `RESOURCE_LOW` | warning | latching, on after 10.0 s, email, Modbus | Memory running low: tell the manufacturer | Free memory (heap or a task's stack) fell below its margin. Note the System screen figures and tell the manufacturer. |
| 12 | `IOB_LOST` | fault | latching, email, Modbus | I/O board not responding | An enabled I/O board does not answer. Check its power, its address switch and the I/O network cable. |
| 13 | `IOB_CONFIG` | fault | email, Modbus | I/O board wrong type or channel settings conflict | An I/O board is not the type expected, or two channel settings conflict. Check the board type and the I/O settings. |
| 14 | `IOB_OUT_FAULT` | alarm | on after 1.0 s, email, Modbus | Output fault: open circuit, short or overheating | An I/O board output reports an open circuit, a short or overheating. Check the load and its wiring. |
| 15 | `IOB_IN_FAULT` | alarm | on after 1.0 s, email, Modbus | Input fault: wire break | An I/O board input reports a wire break or an input chip fault. Check the sensor wiring. |
| 16 | `IOB_SUPPLY` | fault | on after 0.5 s, email, Modbus | I/O board field 24 V supply missing | An I/O board's field 24 V supply is missing. Check its field supply terminals. |
| 17 | `IOB_NODE_RESET` | warning | latching, Modbus | I/O board restarted by its watchdog | An I/O board was restarted by its own watchdog. Acknowledge; report it if it repeats. |
| 18 | `IOB_TEMP_FAULT` | alarm | on after 3.0 s, email, Modbus | Temperature input fault: open, short or out of range | A temperature input is open, shorted, out of range, or its converter failed. Check the sensor and wiring. |
| 19 | `SAFE_MODE` | fault | email, Modbus | Restarted repeatedly: safe mode, application stopped | The unit restarted repeatedly within a short time, so it started without the application (outputs off). Read the last fault, then power-cycle. |
| 20 | `SUPPLY` | warning | on after 2.0 s, off after 2.0 s, email, Modbus | Supply voltage outside 19-30 V | The 24 V supply measured outside 19-30 V. Check the power supply and wiring. |
| 21 | `CAL_DUE` | warning | email, Modbus | Calibration due | A calibrated channel is past its calibration interval. Calibrate it (Calibration page or screen). |
| 22 | `HW_REV` | warning | Modbus | Board revision differs from the factory record | The board's revision straps differ from the hardware revision in the factory record. Check that the core board was not swapped; update the record at factory login. |
| 23 | `SELFTEST` | warning | email, Modbus | Start-up self-test failed: see System information | A start-up self-test failed (System information lists which). See docs/FAULT_CODES.md, self-test checks. |

## Start-up self-test checks

Parameter 333 and `/api/info` `selftest` (PLATFORM.md 5o). A product's own checks are bits 16-23.

| Bit | Check |
|---|---|
| 0 | `image` |
| 1 | `ram` |
| 2 | `rtc` |
| 3 | `settings` |
| 4 | `calibration` |
| 5 | `log_flash` |
| 6 | `net_phy` |
| 7 | `io_port` |
| 8 | `display` |

## Fault record

The last fault before a restart: `/api/info` `last_fault` (code, name, arg), the System screen.

| Code | Meaning |
|---|---|
| 0 | none |
| 1 | a task stopped checking in (name = the task); the watchdog restarted the unit |
| 2 | a task overran its stack (name = the task) |
| 3 | the FreeRTOS heap ran out |
| 4 | a software check failed (name = file or table, arg = line or bad ID) |
| 5 | CPU fault (name = mem/bus/usage/stack, arg = PC, lr = caller) |

## Reset causes

The `power_up` event's arg (its detail says it in words).

| Code | Cause |
|---|---|
| 0 | unknown |
| 1 | power-on |
| 2 | reset pin |
| 3 | software reset (firmware update, restart, after a recorded fault) |
| 4 | watchdog |
| 5 | window watchdog |
| 6 | brown-out |
